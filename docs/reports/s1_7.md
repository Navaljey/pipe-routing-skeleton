## 3. D92 블록 쌍 탐색 예산

- **② 서포트 하한 휴리스틱 — 기각 (D108).** 표 범위 밖 엣지는 서포트 비용 0 이고 서포트 가능 엣지는 최소 10 mm 라, 일관성(consistent)을 지키는 남은 서포트 하한이 0 이 된다 — 확장 감소 0% (20% 기준 미달). 넣지 않았다.
- **③ 블록 쌍만 배관당 2²³ = 8,388,608, 진단 4 × 2²³** (`layered.EXPAND_BUDGET_PAIR`, 출력 `global.search_budget` = {kind: expansions, limit, set: "block_pair", diagnosis_limit}). 단일 블록은 2²² 그대로 — `search_budget` 에 set 키가 없다.
- 단일 블록 회귀 확인: D47 규칙으로 돌린 기본 세트 (`--boundary-rule d47`) 가 PR #29 결과와 205/205 배관 경로·J 동일.

## 4. D93 장애물 속성 · D94 관통 규칙 · D95 관통 피스

- **D93:** 입력 스키마 `obstacles[].supportable`·`penetrable`·`penetration_axis` (기본 false, 축 생략 = 가장 짧은 변), `block_pair.wall_thickness`. 기존 시나리오는 속성이 없어 결과 불변. 블록 안 supportable/penetrable 장애물 = 로더 오류 "S2 예정 — 미지원" (M27).
- **D94:** 관통 축 방향 직관만, 판 양쪽 면에서 엘보 접점까지 ≥ max(3D, r). 라우터: 창 상자 (창 × [a − e, b + e], e = 관통 직관 − r) 는 x 축 엣지만 지나는 부드러운 상자, 관통부 = 서포트 고정점 (`LineSupport(fixed=…)`). 검증기 crossing 모듈 = 같은 판정 함수, 서포트 모듈은 관통점에서 간격을 끊는다 (`support_fixed_points`). Dijkstra 대조 시험 통과 (`tests/test_s1_pair.py`).
- **D95:** 관통 피스 = kg/m × 판 두께, J 분해 `penetration` (블록 쌍 시나리오만), 라우터 비용에 같은 값, 출력 스키마·리포트 열·3D 표시 (관통 피스 마커, hover).
