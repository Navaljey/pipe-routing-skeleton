# S1-7b — 서포트 힌트 API (D100)

작성 2026-10-27. 결정 D100. API 문서 `docs/verifier_api.md` §4. 서포트 표: 사내 표준 기반(비공개), sha256 `ac2ba6a2974b…`.

## 1. 무엇을 만들었나

`pipe_routing/verifier/hint.py` — `SupportHint(scenario, routes)` · `SupportHint.from_session(session)`.

| 함수 | 답 | 부르는 채점 함수 |
|---|---|---|
| `form_at(pipe, pos, axis)` | 검증기가 그 위치에 놓을 서포트 (없으면 None) + (면, 형식) 조합별 사유 | `modules.support_candidates` → `support_std.evaluate` |
| `groupable(a, b, face)` | 두 C 서포트가 D 로 묶일 수 있는가, 아니면 처음 걸린 D82 조건 | `support_group._try` |
| `together_at(pipe, pos, axis)` | D89 함께 받치는 D | `support_group.together_at` |

- 조회 전용. 힌트는 검증기와 같은 Context (배관 순서 = 시나리오 순서) 를 따로 만들 뿐 검증기·Session 상태를 바꾸지 않는다.
- 보지 않는 것: 서포트를 어느 위치에 둘지 (D80 ⑤ 탐욕), D82 보완 간격 재확인 (`spacing_recheck: "not_checked"`), 묶음 좌표 순서 탐욕.

## 2. 완료 기준

| 기준 | 결과 |
|---|---|
| 힌트 답 = 검증기가 실제로 놓는 것 | 합성 시험 (`tests/test_s1_hint.py` 5개) + 실제 세트 대조: A·B·C 6,829건 · D89 1건 **모두 정확히 같음** (형식·면·보강·규격·무게·L·부재) |
| 결과 불변 | 힌트 호출 전후 `verify` 출력 같음 · Session `reports()` 같음 (시험) |
| 호출 비용 | `docs/verifier_api.md` §4 — 중앙 form_at 0.8~2.5 ms · groupable 3~5 ms · together_at 13 ms · 생성 1~31 ms |

대조 방법 (`python -m pipe_routing.verifier.hint_bench`): 출력 JSON 의 경로를 지금 검증기로 다시 판정하면서, 서포트 후보 판정에 실제로 넘긴 반올림 전 위치·축을 기록해 그 값으로 힌트를 묻는다. 처음에는 출력 좌표(반올림됨)로 물어 45° 배관에서 부재 끝점(1 mm 미만)·무게 끝자리(10⁻⁴ kg)가 다른 경우가 있었다 — 입력 반올림 때문이며 판정(형식·면·규격)은 모두 같았다.

|---|---|---|---|---|---|
| 수작업 (D96 + D105 첫 해) | 42 | 0 | 0 | — | — |
| 기본 (D96 + D105 첫 해) | 1,770 | 0 | 12 | 1 | 표면 차 6 · 무게 ≥ 합 3 · L1/L2·간섭 2 |

- groupable ok 2쌍 (proc_009 P003·P004 바닥, dense50_003 P008·P043 천장) 은 검증기가 묶지 않았다 — 둘 다 D82 보완 간격 재확인에서 막힌다 (힌트 범위 밖, 문서에 명시).
- 이 세트들의 검증기 결과에는 D 묶음이 없다 (기준선은 배관을 나란히 보내는 경우가 드물다 — R7). "묶음 = groupable ok" 는 합성 시험으로 확인했다.
- 묶음 후보 쌍 105 중 79 가 표면 높이 차 > 50 mm 로 묶이지 않는다 — V3 가 랙을 만들 때 높이를 맞추는 것이 첫 조건이라는 뜻 (R7).
