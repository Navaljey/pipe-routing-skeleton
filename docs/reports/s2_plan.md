## 1. 결정별 구현

### 1.1 D113 내부 구조재 (M27 범위)

**입력·로더** (`scenario.py`, 스키마)
- 장애물 속성 조합 3종만 허용: 장비 (false, false) · 내부 격벽·데크 (true, true) · 필라·스티프너 (true, false). (false, true) 는 오류.
- D93 의 "블록 안 supportable/penetrable = S2 예정 오류" 를 해제한다.
- 관통 축 `penetration_axis` (없으면 가장 짧은 변, D93) — 격벽·데크는 판이므로 두께 축.
- 선택 필드 `type` 은 지금처럼 자유 문자열. 생성기는 `bulkhead` · `deck` · `pillar` · `stiffener` 를 쓴다 `추정:`.

**검증기 — 지지면** (`support_std.evaluate`, `verifier/modules.py`)
- D80 ③ 후보 면 = 블록 구조면 (D22) + 공유 격벽 (D76) + **supportable 장애물의 면**. 배관 축과 평행하지 않은 법선, 배관 쪽을 향한 면만.
- 면까지 거리 L = 배관 중심 → 면 평면 수직 거리. 표 범위는 D79 ③ 그대로.
- **부재가 그 면 범위 안에 닿아야 한다:** 부재가 면에 닿는 끝점 (앵글 반폭만큼 안쪽) 이 면 사각형 안 `추정:`. 필라처럼 좁은 면은 이 조건으로 거른다.
- 부재 ↔ 장애물 간섭 판정에서 **지지하는 그 장애물 자체는 제외**한다 (지금 블록 면과 같다). 다른 장애물은 지금처럼.
- 후보 수: 장애물마다 6면 → 위치마다 근처 supportable 장애물만 본다 (부재 도달 거리 = 표 최대 L + 100 의 AABB 거름, D84 가속과 같은 방식).
- 면 순서 (동률 깨기, D80 ③): 블록 면 → 공유 격벽 → 장애물 면 (장애물 id 순 · 면 순서 고정) `추정:`.

**검증기 — 관통** (`blockpair.py` 일반화)
- 지금 관통 판정은 공유 격벽 1장 (x 축, 창 제한) 전용이다. 이를 **penetrable 장애물 목록**으로 일반화한다: 판마다 관통 축·두께·면 범위.
- 규칙은 D94 그대로: 관통 축 방향 직관만 (45° 금지), 판 양쪽 면에서 직관 ≥ max(3D, r), 관통부 = 서포트 고정점 (간격 0 으로, 무게 0), 관통비 D95 = kg/m × 판 두께.
- 내부 격벽·데크는 **면 전체가 관통 가능** (창 제한 없음) `추정:` — 블록 쌍 공유 격벽의 창 제한은 그대로 (§7 Q13).
- 관통 구멍 (유효 반경 r 원) 이 판 면 범위 안, 관통부끼리 간격 r₁ + r₂ (D94).
- 관통하지 않고 판과 r 미만 = collision (지금과 같음).

**라우터** (`layered.py`, `support_router.py`, `blockpair.py`)
- 고정층: penetrable 판은 관통 축 방향 엣지만 통과하는 "구멍 뚫린 벽" — 블록 쌍 D91 구현을 판 여러 장으로 일반화. 판의 양쪽 면에서 max(3D, r) + t_θ 첫 꺾임 격자선 (D105 각도별) 을 판마다 추가.
- 서포트 u (D80 ⑨) · 엣지 서포트 비용: `LineSupport` 의 면 목록에 supportable 장애물 면을 더한다. 축 엣지 위에서 면 거리는 일정, 면 범위 조건은 격자선 좌표 구간 → **닫힌 식 유지** (지금 블록 면과 같은 구조).
- 서포트 보조 격자선 (D87 ①): supportable 장애물 면에서 표 끝 안쪽 선 + 면 범위 경계선을 그 장애물이 있는 시나리오의 고정층에만 추가.
- **E1 불변:** 속성 없는 장애물만 있으면 면 목록·격자선·관통 목록이 비어 지금 코드 경로를 그대로 탄다 (조건 분기로 분리, 기본 경로 연산 순서 불변). §0 ② 로 확인.

**생성기** (`generator.py`) — 새 옵션 `internal=True` 일 때만 (기본 꺼짐, 난수 소비 불변)
- 장비 박스를 먼저 기존과 같은 난수로 만든 뒤, 별도 난수열 (`random.Random(seed ^ 상수)`) 로 내부 구조재를 더한다 → 기존 장비·배관 난수 순서에 영향 없음. 배관은 내부 구조재를 본 뒤 생성 (단자 이격·D107 직관 보장).
- 세트 제안은 §2.

**시험:** 필라 면 지지 (C·A 형식 선택이 면 범위로 바뀜) · 면 밖 부재 거부 · 지지 장애물 자신과의 간섭 제외 · 격벽 관통 (수직·직관·고정점·관통비) · 데크 수직 관통 · (false, true) 오류 · Dijkstra 대조 (지지면 확장·관통) · E1 불변 (§0).

### 1.2 D111 밸브

**입력 스키마** (상위 호환)
- 배관 필드 추가: `valves: [{"type": "gate"}]` (S2 는 길이 0 또는 1) `추정:` 이름.
- `valve_positions` 는 properties 에 남기고 required 에서 뺀다. 값이 있으면 **오류** ("D111: 밸브 위치는 입력이 아님 — `valves` 사용") `추정:` (§7 Q8). E1 은 모두 빈 배열이라 영향 없음.
- 타입 일관성 (D33 확장): T2·T4·T6·T8 ⇔ `valves` 1개 이상 `추정:` — 경고로 시작.

**검증기** (`verifier/modules.py` valve 모듈)
- 판정 입력을 `pipe.valve_positions` 에서 **경로 출력** `PipeRoute.valves = [{pos, type}]` 로 옮긴다. 규칙 (직관 위 1 mm · 엘보 위 불가 · 높이 D19 · 전면 D43) 그대로.
- 필요 개수 확인: `valves` 요구 수 ≠ 경로 밸브 수 → valve 위반 (새 메시지).
- J: 밸브 무게 = §3.2 게이트밸브 (지금과 같음). 밸브 몸체 길이는 모델에 없음 (점) — 직관 길이 청구 그대로.
- 기존 수작업 시험 경로 (`tests/test_verifier.py` 밸브 정답/오답) 는 같은 위치를 `PipeRoute.valves` 로 넘기도록 고친다 (판정 결과 같아야 함).

**라우터** (`space.State`, `layered.py`, `astar_fast.py`)
- 상태에 `valve: bool` (밸브 놓음) 추가. 밸브 없는 배관은 항상 True 로 시작 → 지금과 같은 상태 공간·연산 (E1 불변).
- 전이: 직진 중 노드 v 에서 (꺾지 않고 지나가는 노드, 엘보 접선 구역 밖 — D60·D65 엣지 마스크의 깎인 구간 밖) 높이 D19 안이고 전면 D43 여유가 있으면 "밸브 놓기" 전이 (비용 = 밸브 무게, 노드 그대로).
- 전면 판정 = 검증기 `valve_front_free` 와 같은 함수 — 장애물·블록 경계 + **놓인 배관** (배치층) 기준, (노드, 축) 별 캐시.
- 목표 = 도착 ∧ valve. 휴리스틱 h += (valve 아님 ? 밸브 무게 : 0) — 앞으로 반드시 더할 비용의 하한이라 admissible·consistent 유지.
- 지배: 같은 (노드, 방향, …) 에서 valve 가 True 인 쪽이 g ≤ 이면 False 쪽을 지배 (False 는 이후 밸브 무게를 반드시 더한다).
- **밸브 높이 격자선** `추정:`: 밸브 배관 고정층 (구경별 캐시 키에 "밸브 층" 추가, G1 중력관 층과 같은 방식) 에 z = 700 · 1,100 · 1,500 선을 더한다 — 지금 z 격자에 700~1,500 사이 선이 없으면 밸브를 놓을 노드가 없다. 밸브 없는 배관의 층은 그대로 (E1 불변).
- 컴파일 A* 는 상태 배열 `s_v` 추가 — 밸브 없는 배관에서 확장 순서 비트 동일 (D53 시험 그대로 통과).

**다중 배관**: 놓인 배관의 밸브 전면 상자를 나중 배관의 배치층 장애물로 예약할지 → §7 Q4.

**실현 가능성 분류 (D64 방식)** → §7 Q5.

**시험:** 밸브 비트 Dijkstra 대조 · 높이·전면·엘보 위 규칙 정합 (라우터가 놓은 밸브 검증 위반 0) · 밸브 없는 배관 확장 순서 불변 · 수작업 시험 경로 판정 불변.

### 1.3 D112 분기 1개 (정확 풀이)

**입력 스키마** (상위 호환)
- 배관 필드 추가: `branches: [{"id", "nominal_size", "pos", "kind", "dir"}]` (1~5개). 주관은 지금 `start`·`end`.
- 로더: 다리 구경 ≤ 주관 구경 (초과면 오류, D112), 단자 규약 D28·D29·D32 를 다리 단자에도, T3·T4·T7·T8 ⇔ `branches` 1개 이상 `추정:` (경고로 시작).
- `branch_points` 는 properties 에 남기고 required 에서 뺀다. 값이 있으면 오류 (D112: 티 위치는 입력이 아님) `추정:`.
- 다리 단자의 dir·흐름 방향 규약 → §7 Q1.

**출력 스키마** (상위 호환): routes[] 에 `tree` 추가 — `{"main": waypoints, "legs": [{"leg_id", "nominal_size", "waypoints", "tee": {"pos", "angle"}}], "method": "exact" | "sequential"}`. 기존 `waypoints` = 주관 (지금 읽는 쪽 영향 없음). 다리 waypoints 는 티 → 다리 단자 순 `추정:` (흐름 방향은 `flow` 필드로).

**검증기** (branch 모듈 다시 씀 — D112)
- 삭제: "입력 branch_points 와 1 mm 일치".
- 규칙: 티 = 주관 직관 위 (엘보 위 불가) · 분기각 ∈ {45, 90} (주관 흐름 방향 기준, 정의 §7 Q2) · 티 직관 (티 중심 → 다음 관이음 주관 앞·뒤 ≥ 3D_주관, 분기 쪽 ≥ 3D_분기, 티끼리 3D 겹치면 위반) · 다리 구경 ≤ 주관.
- 다리에 bend · gravity_slope (D61, 중력관 다리는 다리 단자 → 티 하향) · support 모두 적용 (D44 "주관만" 수정). collision 은 다리 ↔ 자기 주관 (티 근처 제외 `추정:` — 티 중심에서 r_주관 + r_다리 이내 조각만 제외) ↔ 다른 배관 ↔ 장애물.
- J: 다리 직관 (티 중심부터) × 다리 kg/m + 다리 엘보·서포트. 티 무게 0 (D112).
- 티와 서포트 간격 → §7 Q3.

**기준선 — 분기 1개 정확 풀이** `추정:` 방법
1. 다리 탐색: 다리 단자에서 다리 구경 그래프로 다익스트라 (목표 없음, 예산 안에서 전개) → 노드·도착 방향별 최소 다리 비용 표 `leg[v, d]` (티 쪽 3D 직관을 도착 조건으로 — 마지막 엣지 직진 ≥ 3D_분기).
2. 주관 탐색: 주관 단자 → 단자 A* 에 "티 놓기" 전이 추가 — 직진 중 노드 v 에서 (주관 앞 직진 ≥ 3D_주관) 분기각 45/90 이 되는 다리 방향 d 에 대해 비용 `leg[v, d]` 를 더하고 상태에 "티 놓음 + 티 이후 직진 0" 표시 (뒤 3D 는 직진 길이로 확인). 목표 = 도착 ∧ 티 놓음.
3. 이렇게 하면 라우터 비용 기준으로 세 단자 트리의 최적 (그래프 위, D40) — 단 **다리와 자기 주관의 간섭은 이 합에 안 들어간다.** 최적 트리의 다리 ↔ 주관이 간섭하면 그 (v, d) 를 막고 다시 (최대 k 회 `추정:` k = 8), 그래도 안 되면 순차 근사로 → 출력 `method`.
4. 중력관 (T7·T8): 다리 탐색은 다리 단자에서 하향 (D61, 다리 단자 높이 ≥ 티 높이), 주관 하향은 지금 그대로. 다리 비용 표를 높이 순서로 만들 수 있다.
- 정확 풀이의 정의·간섭 처리 → §7 Q9.

**시험:** 작은 맵에서 모든 티 위치를 열거한 무차별 최적과 정확 풀이 비용 일치 · 다리 규칙 정합 (라우터 트리의 branch·bend·gravity·support 위반 0) · 분기 없는 배관 확장 순서 불변.

### 1.4 D112 헤더 (분기 2~5개, 순차 근사)

- 주관을 먼저 (분기 없는 배관처럼, 단 티 자리 3D 를 남길 수 있게 직진 정보 기록).
- 다리를 구경 큰 순 (같으면 주관까지 거리 먼 순 — 다리 단자 ↔ 주관 중심선 최소거리) 으로, **주관 직관 위 목표 집합** (주관 위 티 가능 노드: 분기각·3D·기존 티와 3D 겹침 없음) 으로 A*. 앞서 놓은 다리는 자기 배관 안의 장애물 (간격 r₁ + r₂).
- 한 다리가 실패하면 그 배관은 실패 (Layer 0 의 해당 다리) — 부분 성공 처리 → §7 Q10.
- 다중 배관 순차 배치 (D50): 분기 배관은 트리 전체를 한 배관으로 배치 · rip-up. 분기 단자에도 D59 단자 예약을 둔다 `추정:`.
- 예산 → §7 Q6.

### 1.5 D114 힌트

- `SupportHint` 옆에 `FittingHint` (같은 Context, 조회 전용): `tee_at(주관, 위치, 분기 방향, 분기 구경)` → {ok, reasons: [직관 위, 분기각, 3D 앞, 3D 뒤, 3D 분기, 구경]} · `valve_at(배관, 위치, 축)` → {ok, front_dirs, reasons: [직관 위, 높이, 전면]}.
- 검증기 branch·valve 모듈과 같은 함수를 부른다. 대조 시험 (검증기가 판정한 모든 티·밸브에 대해 힌트 답 = 판정) + `hint_bench` 확장으로 호출 비용 → `docs/verifier_api.md` §4.

### 1.6 D115 생성기 · 세트

- 옵션 `internal`·`valves`·`branches` (모두 기본 꺼짐). 켜지 않으면 난수 소비·출력 비트 동일 (§0 시험).
- 켜면 별도 난수열 (seed 에서 유도) 로 추가 생성 → 같은 시드에서 기존 장비·단자 배치는 그대로 유지되는 장점도 있다 (같은 장비 배치 위의 비교).
- 학습용 3xxxxxxx · 검증용 4xxxxxxx 시드에서 같은 함수로 생성 (CLI `--seed`, 범위 확인은 하지 않음 — v3_contract §d 가 규칙).
- 헤더 분기 수 1~5 고루 (균등), 다리 구경 = 주관 이하 구경 중 균등.
