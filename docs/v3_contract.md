# V3 개발 계약 (D71)

> V3 세션을 시작하면 이 문서를 가장 먼저 읽는다.
> **skeleton 은 심판, V3 는 선수다.** 심판은 V3 가 고치지 않는다 (§f).
> V3 = **학습 기반 방법 (지도학습·강화학습·혼합 무관)** (D103). 조건은 방법과 관계없이 같다: 슬롯 인터페이스 (D3·D49·D50 ⑧), 심판 불변 (D71), 결정적 예산 (D97), 판정 (D98·D99). 학습 시간은 곡선에서 빼고 추론 시간은 넣는다 (D68).

정본 우선순위는 CLAUDE.md 를 따른다. 이 문서는 CLAUDE.md 의 결정(D)을 V3 개발자 관점으로 묶은 것이며, 둘이 어긋나면 CLAUDE.md 가 맞다.

## (a) skeleton 구조 요약

```
입력 JSON (§7.1, schemas/scenario_input.schema.json)
  → pipeline.run(scenario, router=..., planner=..., time_limit=60)
       planner(scenario, router, time_limit) → PlanResult          ← 다중 배관 슬롯 (순서·rip-up)
           router(scenario, pipe, time_limit, placed) → RouteResult ← 라우터 슬롯 (배관 1개)
       verify(...)  검증기 Layer 0 (D44) — 실제 기하로 판정
       J 분해 · 출력 JSON (§7.2, schemas/scenario_output.schema.json) · 리포트
```

**슬롯 시그니처**
- 상세는 `docs/slots.md`.
- 라우터는 놓인 배관 `placed = [(Pipe, waypoints)]` 를 장애물로 본다. 이격은 r₁ + r₂ (D17, D50②).
- 반환값은 꺾임점 목록(waypoints)이다.

**기준선 라우터 (`layered_router_a`, D55)**
- 고정층: 고정 장애물만의 escape graph, 구경별 1회 생성·캐시.
- 배치층: 놓인 배관·단자 예약이 막는 엣지를 표시한다.
- 탐색: 컴파일 A* (D53).
- 비용: 직관 + 엘보 + 추정 서포트 (D57).
- 그 그래프 위에서 J 최적이다 (D40).

**꺾임 판정 (D45·D47·D48·D60·D65)**
- 엘보 접선 길이 규칙을 따른다.
- 엘보 호(R = 1.5D)는 실제 형상으로, 장애물·놓인 배관과 함께 판정한다.

**단자 예약 (D59)**
- 아직 놓이지 않은 배관의 단자 직진 구간은 다른 배관이 지나갈 수 없다.
- 구간 길이: 노즐 = max(§3.3, t₉₀), 경계 = max(3D, r) + t₉₀ (D96).

**중력관 계단 규칙 (D61~D64)**
- 상향 금지, 수평 구배 0 허용.
- 마지막 하향 이후 누적 수평 길이 ≤ L_max (§3.5).
- 규칙상 불가능한 배관은 별도 집계한다.

**격자 기본값 = G0** (D66)
- G1 은 S1-4 판정에 따라 중력관 그래프 기본값이 될 수 있다.
- G2 는 품질 옵션이다.

**다중 배관 기준선 (D50·D52)**
- 호칭경 내림차순으로 순차 배치하고, rip-up 은 시나리오당 최대 3회 (first-solution 기준선).
- anytime 기준선은 S1-5 (D68). **승리 기준 곡선 = S1-8 E1 동결 측정분** (S1-6·S1-7 반영 후). S1-5·S1-5b 곡선은 서포트 규칙(S1-6) 이전이라 무효다 (D83).

**V3 역할 (D104, D8 해제)** — 역할을 나눈다.
- 단일 배관: A* 안의 학습 휴리스틱 (포컬 탐색) — **속도** 담당. 같은 그래프에서 A* 는 이미 J 최적이라 단일 배관 학습의 이득은 속도뿐이다.
- 다중 배관: 협상·가격 반복 + 순차 확정 위에서 순서·랙 형성 학습 — **품질** 담당. 품질 이득은 다중 조정 (R2·R7) 과 표현 해상도 (R4, D102) 에서만 나온다.
- 설계 문서: GNARL 레포 `Navaljey/pipe-routing-GNARL` `docs/design_v3_architecture.md` (PR #4). skeleton 은 링크만 둔다.

V3 결과는 반드시 이 검증기로 판정한 출력 JSON 이어야 한다. V3 자체 판정은 결과로 인정하지 않는다.

**판정 결과는 결정적이어야 한다 (D72).**
- 같은 입력·같은 코드·같은 시드면, 머신 부하·병렬 수와 상관없이 같은 출력(경로·J·실패 분류)이 나와야 한다.
- 시간 제한은 알고리즘이 정의하는 결정적 예산으로 건다. 기준선은 배관당 A* 확장 상태 수 상한이다 (2²², D73 — 머신 속도 환산값이 아니라 기준선의 정의).
- **V3 예산 (D97):** 2²² 는 기준선 정의이며 V3 에 적용되지 않는다. V3 는 자기 결정적 예산을 정의해 제출한다 — **단위** (예: 추론 스텝 수·노드 평가 수·확장 수) · **계산법** · **시드**.
- 무작위 요소는 시드를 고정하고, 시드를 출력에 기록한다.

**판정 축 (D98)** — **벽시계 시간-품질 곡선** (D68: 같은 머신, 추론 시간 포함, 학습 시간 제외, D77 사전식). 벽시계는 고정 조건(동시 실행 수·머신 사양 기록)에서 잰다. **확장 수는 보조 진단 지표로 보고만 한다** — 확장 개념이 방법마다 달라 판정에 쓰지 않는다.

**구조적 보장 (D99)** — 알고리즘의 보장 (예: 포컬 탐색 (1+ε)) 은 설계 근거로 인정하되, **판정은 E1 측정으로 한다.** 그런 보장은 라우터 비용 기준이고 판정은 검증기 J 다. 예산 안 성공 수도 확장 순서에 따라 달라질 수 있다. 보장을 주장하는 제출물은 **"라우터 비용 기준 보장"** 과 **"검증기 J 측정값"** 을 둘 다 보고한다.

## (b2) 탐색 상태 정의 (기준선 A*)

기준선 라우터의 탐색 상태 = `space.State` (파이썬) · 컴파일 A* 상태 배열 `s_*` (`astar_fast._search_generic`). V3 가 같은 규칙을 지키려면 아래 성분이 필요하다 (V3 가 상태를 어떻게 표현할지는 자유 — 판정은 검증기, §b). 모든 성분에 대해 **지배 가지치기**는 "같은 (노드, 방향) 에서 이후 허용 이동이 포함관계로 넓고 g 가 작거나 같으면 버린다" 이며, 최적성을 보존한다 (Dijkstra 대조 시험, D40 ①).

| 성분 | 정의 | 갱신 규칙 | 지배 | 결정 | 코드 |
|---|---|---|---|---|---|
| node · dir | 격자 노드, 진입 방향 18종 (축 6 + 평면 내 45° 12) | 엣지를 따라 이동. 편향각 ∈ {0, 45, 90, 135} 만 (180° 역행·다른 평면 45° 사이 전환 금지) | 키 | D37·D15 | `space.State.node·dir`, `s_node·s_dir` |
| run | 마지막 꺾임 (또는 start 단자) 이후 직진 길이 mm, 상한 max(§3.3, t_bend + t₁₃₅) | 직진이면 run + 엣지 길이, 꺾으면 엣지 길이. 꺾으려면 run ≥ 필요 길이 (D45: 꺾임 사이 ≥ max(§3.3, t_앞 + t_뒤), start → 첫 꺾임 ≥ max(§3.3, t), 경계·관통 단자 쪽 ≥ max(3D, r) + t — D94·D96) | run ≥ | D37·D45·D94·D96 | `State.run`, `s_run`, 필요 길이 `need_m`, 상한 `run_cap` |
| bend | 마지막 꺾임 편향각 등급 (0 = 아직 안 꺾음, 45·90·135) | 꺾으면 그 각도, 직진이면 그대로 | bend ≤ (접선 길이가 각도에 단조 증가) | D45 | `State.bend`, `s_bend` |
| mask (ends) | 들어온 엣지의 끝에서 허용되는 꺾임 등급 4비트 (0/45/90/135) | 엣지 마스크 16비트 (시작 등급 i × 끝 등급 j: 양 끝을 그 엘보 접선만큼 깎은 직관이 장애물·놓인 배관·예약·부재와 이격 통과) 에서, 이번 꺾임 등급 i 행의 4비트를 가져온다. 마스크가 이번 꺾임을 허용하지 않으면 그 이동 불가 | 마스크 ⊇ | D60·D65·D59·D90 | `State.ends`, `s_mask`, 엣지 `emask` (고정층 ∧ 배치층, D67 캐시) |
| h (중력관) | 마지막 하향 이동 이후 수평 누적 길이 mm (압력관은 항상 0) | +z 성분 엣지 금지. 하향 (수직 하향·수직면 45° 하향) 이면 0. 수평이면 h + 길이, h ≤ L_max (§3.5) 이어야 한다 | h ≤ | D61~D63 | `State.hz`, `s_h`, 공용 식 `gravity.step` (검증기 gravity_slope 와 같은 함수) |
| u (서포트) | 마지막 서포트 가능 지점 이후 지지 없이 온 정규화 길이 Σ 길이 / 그 방향 최대 간격 (§3.6), ≤ 1 | 엣지 위 서포트 가능 구간 (면 거리·형식 표 범위·고정 장애물 막힘, 닫힌 식) 이 있으면 마지막 가능 점 이후 길이로 다시 시작, 없으면 u + 길이 / 간격. 꺾을 때 **꺾임 구역** 2·t_θ / 수평 간격을 더한다 (D87 ② — 엘보 호 위는 서포트 불가). 단자 = 고정점 (u = 0, D44·D96). **관통부 = 고정점** — 블록 쌍 창을 지나는 x 축 선은 격벽 중심에서 u = 0, 무게 0 (D94). 놓인 배관에 의한 부재 막힘·D 묶음은 라우터에서 보지 않는다 (근사, D80 ⑨·D83 ①) | u ≤ | D80 ⑨·D87 ②·D94 | `State.su`, `s_u`, 엣지 표 `spack` (가능 점 이전 a · 이후 b · 안쪽 불가 최대 g), 꺾임 `bendu`, 공용 식 `support_router.support_step`, 고정점 `support_router` (D94)·`layered` 관통 층 |
| g | 지금까지 라우터 비용 = 직관 × kg/m + 엘보 (§3.4) + 추정 서포트 (D80 ⑨) + 관통 피스 (D95) | 엣지마다 더한다 | g ≤ | D49·D57·D80·D95 | `s_g`, 엣지 서포트 비용 `scost` |

휴리스틱 h_A* = 남은 유클리드 거리 × kg/m + 최소 꺾임 수 × 45° 엘보 (D41, admissible·consistent). 서포트 하한 강화는 기각 (D108). 예산 = 배관당 확장 상태 수 (§b, D97 — 기준선 정의).

## (c) 교체 — 선수 (V3 자유)

- 라우터 슬롯·다중 배관 슬롯의 **내부 전부**
- **공간 표현** (D9·D102)
  - escape graph 를 쓸 의무가 없다: 격자·연속 공간·샘플링 무엇이든 된다. **라우터 슬롯 안의 표현 변경 (해상도 포함) 은 V3 범위다** (D102).
  - 단, 판정은 같은 검증기로 한다. 라우터가 규칙을 어기면 그 배관은 실패로 집계된다.
  - 표현을 바꿔 얻은 J 이득은 §e 대로 나눠 보고한다 (D102).
- 학습 방법 (지도학습·강화학습·혼합 무관, D103)·신경망 구조·탐색 전략·휴리스틱
- 학습용 시나리오 — 같은 생성기(`pipe_routing.generator`)의 학습용 시드 범위(§d) 또는 별도 생성 규칙

- 같은 생성기에서 시드 범위만 나눈다. **확정 (2026-10-27 소유자, S1-8 평가셋 E1, D70)** — 세 범위(평가 · 학습용 · 검증용)는 겹치지 않는다.

  - 검증용 (모델 선택·튜닝): `40000000 ~ 49999999`
- 생성기 설정(배관 수·채움률·구경·중력관 비율 등)은 바꿔도 된다. 바꾼 설정은 결과와 함께 기록한다.

## (d2) 1단계 라벨 (A* 정답) 생성 규약 (D86)

- **S1-6 병합 이후의 A* 결과만 라벨로 쓴다.** S1-6 은 라우터 서포트 추정(D80 ⑨)을 바꿔 A* 경로를 바꿨다 — 그 이전 결과는 사용 불가.
- **S1-7 의 D96 (경계 단자 강제 직관)·D105 (첫 꺾임 격자선 각도별) 이후 결과만 쓴다** — 둘 다 단일 블록 A* 경로를 바꾼다 (빈 맵 단독·순차 배치 모두). 그 이전 라벨은 다시 만든다 (D86 ③).
- 그 밖에: D90 (서포트 부재 예약, PR #28) 은 순차 배치 경로만 바꿨고, S1-6b(증분 검증)·D90 시간 단축·D109 진단 도구는 결과 불변이다. S1-7 의 블록 쌍(D91~D95)은 별도 세트다.
- **학습용 시드 범위(§d) 시나리오로만** 만든다. E1 평가 시나리오(`scenarios/`, 평가 시드 범위)로 만들지 않는다.
- 라벨마다 skeleton 커밋 · 서포트 데이터 해시(`support_standard.sha256`) · 격자 변형(`grid_variant`)을 기록한다.
- E1.x 규칙 변경(§f)이 있으면 라벨을 다시 만든다.

## (e) 결과 제출

- 같은 `pipeline` 과 같은 검증기로 평가 세트를 실행한다.
  - 라우터는 `pipeline.run(router=...)`, 다중 배관은 `pipeline.run(planner=...)` 로 꽂는다.
- 제출물:
  - 시나리오별 출력 JSON (스키마 통과)
  - 시간-품질 곡선 (S1-5 도구, D68)
- 함께 기록할 것:
  - 코드 커밋
  - 모델 체크포인트 (해시)
  - 하드웨어 (CPU·GPU·메모리)
  - 병렬 수
- 시간 계산:
  - 학습 시간은 따로 보고하고, 곡선 x 축에 넣지 않는다.
  - 추론 시간(모델 적재 제외, 배치 결정 포함)은 곡선 x 축에 넣는다.
- 비교 규칙: 같은 머신·같은 예산에서 기준선 곡선보다 위면 우위 (D68). **"위" = D77 사전식 판정**:
  1. **완전 성공 시나리오 수** — 규칙상 가능한(D64) 배관이 모두 Layer 0 를 통과한 시나리오 수. 분모에서 빼는 것은 D64 규칙상 불가능 배관뿐이다. "단독 도달 불가" 배관은 증명된 불가능이 아니므로 분모에 남는다 (D34).
  2. **통과 배관 수.**
  3. **J_total** — 1·2 가 같을 때(같은 통과 집합)만 비교한다. 통과 집합이 다르면 "공통 통과 배관 J" 를 보조 지표로만 보고한다.
- 출력 global 의 `full_success` · `required_pipes` · `required_passed` · `excluded_infeasible` 가 1 의 근거다.
- **J 이득 보고 (D102)** — 둘로 나눈다: ① 기준선 G0 대비 ② 참조 품질선 (G2 1 m, D70 — S1-8 측정) 대비. **② 를 넘는 이득만 조정·학습 이득으로 인정한다** (R4). ① 과 ② 사이는 표현 해상도 이득이다.
- **Σ 단독 J 참고치 (D101)** — 출력 global `solo_reference` · routes[] `solo`: 각 배관을 다른 배관·단자 예약·부재 예약 없이 기준선 A* (그 세트의 상한) 로 단독 라우팅한 경로의 단독 검증기 J. 간격 = Σ J_다중 / Σ J_단독 − 1 ("단독 통과 ∧ 다중 통과" 배관만), 단독 실패 수. 공유 서포트 (D 묶음·D89) 가 있으면 "하한 아님, 참고치". 예산 밖 보고용 (곡선 시간에 넣지 않음), 결정적.
- **보장 주장 (D99)** — 보장을 내세우면 "라우터 비용 기준 보장" 과 "검증기 J 측정값" 을 함께 낸다.

## (e2) 평가셋 판과 V3 단계별 승리 조건 (D70)

**평가셋 판**
- 세트 = 같은 종류 시나리오 묶음.
- E판 = 세트 구성 + 채점 규칙 + 기준선 결과의 동결 묶음.
- 판 올림 규칙:
  - 세트 추가 → 다음 판 (E1 → E2).
  - 같은 세트의 규칙 수정 → 소수 판 (E1 → E1.1, §f 절차).
- 새 판은 이전 판의 세트를 모두 포함한다.

| 판 | 세트 | 준비 시점 |
|---|---|---|
| E1 | 수작업 · 기본 · 계단 · 밀집 30 · 밀집 50 · 블록 쌍 | S1-8 |
| E2 | E1 + 큰 맵 세트 | V3 2단계 전 |
| E3 | E2 + 밸브·분기 세트 (skeleton S2, R6) | V3 4단계 전 |

**V3 단계별 승리 조건**

| 단계 | 범위 | 학습 | 슬롯 | 승리 조건 | 평가 판 |
|---|---|---|---|---|---|
| 1 | 단일 배관 | 학습 기반 (예: A* 정답 모방) | 라우터 슬롯 | A* 대비 J ≤ +1% `추정:` · 성공 수 같음 — **이 J·성공 조건을 만족하면서 벽시계 감소** (D98, 확장 수는 보조 진단) | E1 |
| 2 | 맵 확장 | 학습 기반 (예: 오프라인 A* 모방) | 라우터 슬롯 | 큰 맵에서 벽시계 시간 기울기 감소 (D98 — 확장 수 기울기는 보조 진단) | E2 (+ E1 회귀) |
| 3 | 다중 배관 | 학습 기반 방법 (지도학습·강화학습·혼합 무관, D103) — 2단계 망은 라우터로 고정, 조율 망 신규 | 다중 배관 슬롯 | 같은 시간에 기준선 곡선 위 (D68·D98) — ① 완전 성공 시나리오 수 → ② 통과 배관 수 → ③ J_total 순 (D77) | E1 밀집 곡선 + E2 회귀 |
| 4 | 분기·밸브·경계 관통점 | 학습 기반 방법 (D103) + 모듈 추가 | 다중 배관 슬롯 + 모듈 | 기준선 곡선 위 (D77 순서) | E3 (이전 전부 회귀) |

"회귀" = 이전 판 세트에서 이전 단계 승리 조건을 계속 지킨다. 역할 분담은 D104 (§a): 1·2단계 = 속도, 3·4단계 = 품질.

## (f) 심판 변경 절차

V3 개발 중 규칙·검증기·지표·평가셋에서 문제를 발견하면 **V3 쪽에서 고치지 않는다.**

1. 문제를 기록하고 skeleton 소유자에게 보고한다. 재현 시나리오와 기대 판정을 함께 낸다.
2. skeleton 에서 결정(D 항목)을 추가하고 심판 코드를 고친다.
3. 평가셋 판을 올린다 (D70): 같은 세트의 규칙 수정 = E1 → E1.1, 세트 추가 = E1 → E2 (`docs/eval_set_E*.md`). 새 판은 이전 판 세트를 모두 포함한다.
4. 기준선을 재측정하고, 그 버전으로 V3 를 다시 평가한다.

다른 평가셋 판끼리의 결과는 직접 비교하지 않는다.
