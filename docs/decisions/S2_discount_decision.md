# 결정 초안 — 공용 서포트 유도용 할인 (D141, D126 확장)

**작성일:** 2026-11-26 (사양 세션 초안)
**상태:** **초안 — V3·OPT 검토 → 수정 → 소유자 승인 대기.** 승인 전에는 skeleton·V3·OPT 모두 구현하지 않는다.
**번호:** 옮겨 적을 때 번호가 이미 쓰였으면 비어 있는 다음 번호를 쓰고, 이 파일의 번호도 함께 고친다.
**관련:** D40 ①·D41·D57·D80 ⑨·D81·D82·D89·D99·D101·D102·D125·D126 · R7 · V3 설계안 D-t (끌어당김 항) · §35 (음의 가격은
rg 하한을 깬다) · §37 (서포트 인식 통행료 S) · OPT.Dec8 §7.6 (랙 개선 갈래) · OPT.Req14

## 배경

- **협상만으로는 J 가 "각자 혼자 깐 합" (Σ 단독 J, D101) 아래로 못 내려간다.** 다중 J 는 단독 합보다 기본 +0.3 % ~
  밀집 50 +2.8 % 클 뿐이다. 그 아래로 내려가는 유일한 길은 공용 서포트 (D 형식 묶음 D82 · 함께 받치기 D89, 몫 D81) 다.
  서포트는 라우터 비용의 약 9 % 다.
- 기준선은 랙을 만들지 않는다 (D88 보류 — 절감 약 45 kg). 랙 형성은 선수 몫 (R7).
- V3 는 "끌어당김 항" (D-t — 묶일 수 있는 칸의 비용을 깎음) 을, OPT 는 "랙 개선 갈래" (§7.6 — 작은 배관을 큰 배관 높이에
  맞춰 다시 깔기) 를 설계했다. **둘 다 구현하지 않았다.** 지금 V3 T 의 서포트 인식 통행료 (S) 는 다른 배관 서포트 자리를
  **피하게** 하는 것이지 같이 쓰게 하는 것이 아니다.
- **막힌 곳:** 끌어당김 = 음의 추가 비용. 그런데
  ① D126 공식 인자 `extra_cost` 는 0 이상만 받는다 (`layered._check_extra` — 음수면 오류).
  ② 선수가 쓰는 하한 rg (D125 — 할인 전 비용으로 미리 계산) 가 할인된 길의 실제 비용보다 커지면 A* 가 그 길을 미루다
     놓친다 (하한이 실제를 넘으면 최적성이 깨진다, D40 ①).
  ③ 칸 비용이 0 아래로 가면 rg 를 구하는 최단거리 계산 자체가 깨진다.

## D141 공용 서포트 유도용 할인 (D126 확장)

① **할인 허용 범위.** `extra_cost[e]` (엣지 e, (N, 18)) 는 **−scost[e] 이상**이면 된다 — 음수를 허용하되, 그 엣지의 추정
서포트 비용 (`scost`, D80 ⑨ — 관통비 D95 포함) 을 넘게 깎지 못한다. 따라서 어떤 엣지 비용도 배관 자체 비용
(길이 × kg/m) 아래로 내려가지 않는다. 하한을 넘는 음수·유한하지 않은 값은 지금처럼 오류.
`추정:` scost 에 관통비가 섞여 있어 이론상 관통비까지 깎을 수 있다 — 물리적으로는 서포트 몫만 깎는 것이 맞다. 서포트 몫만
따로 노출할지 (공개 배열 추가) 는 V3·OPT 검토에서 정한다.

② **D41 h 는 그대로 유효하다.** D41 h = 남은 직선 거리 × kg/m + 최소 엘보 — 서포트 항이 없으므로 ① 범위 안의 할인으로는
실제 남은 비용을 넘지 않는다. 엘보·관이음 비용은 할인 대상이 아니다 (엣지에만).

③ **h_lower 는 할인을 포함한 하한이어야 한다 (선수 책임).** D126 규칙 그대로 — h_lower 는 extra_cost 를 포함한 남은
비용의 하한. 할인을 쓰면 rg 를 할인 포함 비용으로 다시 구해야 한다. **skeleton 이 도움 함수를 낸다:**
`layered.relaxed_lower_bound(g, pipe, extra_cost)` = D125 rg 정의 (완화 그래프 — 방향·직진·꺾임·u·구배 제약을 푼 노드
그래프, 엣지 무게 = 길이 × kg/m + scost + extra_cost, emask == 0 제외, 목표에서 역방향 Dijkstra) — ① 범위면 엣지 무게
≥ 0 이라 Dijkstra 가 성립한다. D125 참조 속도선 (A* + rg) 도 같은 함수를 쓴다 (D71 — skeleton 이 자기 레포에 구현).

④ **할인은 탐색 비용에만 들어간다.** 지도·J·support_est 는 그대로 (D126 과 같음). J 는 검증기가 D82·D89 로 실제 묶은
결과로만 낮아진다 — 할인을 받고도 묶이지 않으면 J 는 줄지 않는다. 받아들이기는 검증기 점수로 (D75·D99, OPT §7.7).

⑤ **결과 불변.** extra_cost 가 None 이거나 0 이상이면 지금과 비트 동일 (E1 첫 해 41 바이트 동일 · V3 §40 결과 불변).

⑥ **시험 (skeleton):** (a) 할인 ① 범위 안 → 가지치기 없는 Dijkstra (같은 extra_cost) 와 라우터 비용 일치
(b) relaxed_lower_bound ≤ 실제 남은 비용 (최적 경로 위 모든 상태) (c) 범위 밖 음수 → 오류 (d) None·0 이상 → 비트 동일
(e) 결정성 병렬 1/4.

⑦ **선수 쪽 쓰임 (참고, 선수 내부 자유):** 끌어당김 칸 = `support_hint.groupable` · `together_at` 로 "이 칸에 오면
다른 배관과 묶인다" 를 판정한 칸. 할인 크기는 선수가 학습·검증 시드로 정한다 (E1 금지). V3 협상 (가격 + 할인) 과 OPT 랙
개선 갈래가 같은 통로를 쓴다.

## V3·OPT 에 묻는 것 (검토 요청)

1. 할인 범위 = −scost 로 충분한가, 서포트 몫만 따로 노출 (공개 배열 추가) 이 필요한가.
2. relaxed_lower_bound 의 호출 비용 — 협상 반복마다 배관마다 다시 구하는 비용이 감당되는가 (지금 V3 rg 구현과 비교).
3. 높이 맞춤 (D82 표면 높이 차 ≤ 50 mm) 에 필요한 격자선을 선수가 지도에 더하는 방법 (D102 — 선수 범위) 에 skeleton 쪽
   도움 (공개 함수) 이 필요한가.
4. 할인과 간섭 가격이 같은 칸에서 상쇄되는 문제 (V3 설계안 D-t 위험) 를 어떻게 다룰 계획인가 — 계약이 아니라 선수
   설계지만, 측정 보고 항목 (할인 받은 칸 · 실제 묶음 수 · 묶음으로 줄어든 J) 을 정해 둔다.
