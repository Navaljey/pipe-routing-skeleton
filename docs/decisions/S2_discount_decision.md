## 배경

- **협상만으로는 J 가 "각자 혼자 깐 합" (Σ 단독 J, D101) 아래로 못 내려간다.** 다중 J 는 단독 합보다 기본 +0.3 % ~
  밀집 50 +2.8 % 클 뿐이다. 그 아래로 내려가는 유일한 길은 공용 서포트 (D 형식 묶음 D82 · 함께 받치기 D89, 몫 D81) 다.
  서포트는 라우터 비용의 약 9 % 다.
- 기준선은 랙을 만들지 않는다 (D88 보류 — 절감 약 45 kg). 랙 형성은 선수 몫 (R7).
- V3 는 "끌어당김 항" (D-t — 묶일 수 있는 칸의 비용을 깎음) 을, OPT 는 "랙 개선 갈래" (§7.6 — 작은 배관을 큰 배관 높이에
  맞춰 다시 깔기) 를 설계했다. **둘 다 구현하지 않았다.** 지금 V3 T 의 서포트 인식 통행료 (S) 는 다른 배관 서포트 자리를
  **피하게** 하는 것이지 같이 쓰게 하는 것이 아니다.
- **막힌 곳:** 끌어당김 = 음의 추가 비용. 그런데
  ① D126 공식 인자 `extra_cost` 는 0 이상만 받는다 (`layered._check_extra` — 음수면 오류).
  ② 선수가 쓰는 하한 rg (D125 — 할인 전 비용으로 미리 계산) 가 할인된 길의 실제 비용보다 커지면 A* 가 그 길을 미루다
     놓친다 (하한이 실제를 넘으면 최적성이 깨진다, D40 ①).
  ③ 칸 비용이 0 아래로 가면 rg 를 구하는 최단거리 계산 자체가 깨진다.

## D141 공용 서포트 유도용 할인 (D126 확장)

① **서포트 몫 공개 배열 `ssup` (읽기 전용, D126 공개 배열에 추가).** 엣지별 추정 서포트 몫 (N, 18) — `scost = ssup + 관통비
(D95)`. 단일 블록 E1 은 관통비가 없어 `ssup == scost`. 블록 쌍 창 · E2 내부 격벽·데크 엣지는 관통비가 따로 있다.

② **할인 허용 범위 = `extra_cost[e] ≥ −ssup[e]`.** 서포트 몫까지만 깎는다 — 관통비·배관 자체 비용 (길이 × kg/m) 은 깎을 수
없다 (랙 유도 할인이 관통하는 길을 싸게 만드는 부작용 차단, OPT 회신 1). 하한을 넘는 음수·유한하지 않은 값은 오류.

③ **D41 h 는 그대로 유효하다** (서포트 항 없음). 엘보·관이음은 할인 대상이 아니다 (엣지에만).

④ **h_lower 는 할인을 포함한 하한이어야 한다 (선수 책임).** 할인을 쓰면 rg 를 할인 포함 비용으로 다시 구하거나, 할인 최대치
(−ssup) 를 넣은 rg 를 배관당 한 번 구해 반복 내내 쓴다 (약하지만 늘 유효 — V3 회신 ②). skeleton 도움 함수
`layered.relaxed_lower_bound(g, pipe, extra_cost)` = D125 rg 정의에 extra_cost 를 더한 엣지 무게 (≥ 0) 로 역방향
Dijkstra. **선수가 하한을 부풀리면 (예: V3 h_lower = 1.1 · rg, 2026-11-24) 제출 때 적는다** — 그 탐색은 라우터 비용
최적을 보장하지 않으며, 판정은 검증기 J 측정으로 한다 (D99).

⑤ **할인은 탐색 비용에만.** 지도·J·support_est 는 그대로. J 는 검증기가 D82·D89 로 실제 묶은 결과로만 낮아진다.
받아들이기는 검증기 점수로 (D75·D99).

⑥ **높이 맞춤 조회 `support_hint.groupable_levels(pipe, partner, face)`** (D100·D128 방식 — 조회 전용·결과 불변, 검증기와
같은 함수). 상대 배관의 수평 직관 구간·지지면을 주면 "이 배관이 이 높이 (중심 z) 로 오면 D82 묶음 조건 (지지면 쪽 표면
높이 차 ≤ 50 mm · L1·L2 표 범위) 을 만족한다" 는 z 구간 목록을 돌려준다. OPT.Stage2 에서 D82 후보 쌍이 묶이지 않은 주된
이유가 표면 높이 차 > 50 mm 였다 (밀집 50 24 ~ 27 쌍).

⑦ **고정층 추가 좌표 공식 인자.** 고정층 생성에 배관별 추가 축 좌표 `GridSpec(extra={"x": [...], "y": [...], "z": [...]})` —
결정적, 캐시 키에 포함, None = 비트 동일. 지도 판정은 기존 같은 함수 (D38·D65). 소스 패치를 없앤다 (D126 의 목적).
선수가 쓰면 J 이득은 D102 대로 ① G0 기준선 대비 ② 참조 품질선 대비로 나눠 보고한다.
`추정:` 지도 전체를 다시 만드는 방식이다 — 배관 쌍마다 변형을 만들면 지도 수·메모리가 는다. "구역 한정으로 선 몇 개만
더하는" 방식 (OPT 회신 3 (나)) 은 D141 범위 밖, **M38** 로 둔다.

⑧ **결과 불변.** extra_cost None·0 이상, GridSpec.extra None 이면 지금과 비트 동일 (E1 첫 해 41 바이트 동일 · V3 §40
결과 불변).

⑨ **skeleton 시험·측정:** (a) 할인 ② 범위 안 → 가지치기 없는 Dijkstra (같은 extra_cost) 와 라우터 비용 일치
(b) relaxed_lower_bound ≤ 실제 남은 비용 (최적 경로 위 모든 상태) (c) 범위 밖 음수 → 오류 (d) None·0 이상·extra None →
비트 동일 (e) 결정성 병렬 1/4 (f) ssup + 관통비 = scost (블록 쌍·내부 구조재 세트) (g) groupable_levels 대조 —
돌려준 높이로 옮긴 쌍이 검증기에서 D82 로 묶인다 (h) **측정:** relaxed_lower_bound 1 회 호출 시간 (E1 크기 지도 —
기본·밀집 50) · 추가 좌표 고정층 생성 시간·메모리 (추가 선 10·50·200 개).

⑩ **선수 측정 보고 항목 (V3·OPT 공통):** 할인 받은 엣지 수 · 할인 받은 엣지를 실제로 지난 길이 · 할인 경로를 택한 배관 수 ·
새로 생긴 D82·D89 묶음 수와 묶음 무게 (shared_support_kg) · 할인 없음 대비 검증기 J 차 (다른 원인과 분리) · D101 간격 ·
"할인은 받았지만 묶이지 않은" 비율 · 추가 좌표를 썼으면 그 개수와 D102 분리.

⑪ **선수 내부 (참고):** 끌어당김 칸 판정 · 할인 크기 · 간섭 가격과의 관계 (V3: 끌어당김이 켜진 쌍은 그 쌍의 서포트 인식
통행료 S 를 뺀다 `추정:` · OPT: 놓인 배관은 단단한 장애물이라 상쇄 없음) 는 선수가 학습·검증 시드로 정한다 (E1 금지).
