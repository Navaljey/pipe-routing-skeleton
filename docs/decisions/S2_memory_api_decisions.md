## D126 저장 형식 축소 (L3) + 지도 조회 API 규칙

### 배경

메모리 보고서 §2·§4: S2-1 내부 구조재 시나리오 (가) 가 13 GB 상한에서 끝나지 못했다. 원인 셋 중 둘 (층 캐시 누적·밀집 서포트 표, A* 배열 증가의 순간 최대) 을 L3 가 직접 줄인다. 계산: 층당 약 1.2 → 0.5 GB, (가) 가 D127 과 함께 동시 2 실행 (실행당 약 6.5 GB) 에 들어온다.

선수 레포 확인 (2026-11-20): **V3 는 skeleton 지도 내부 배열을 직접 읽고 일부를 직접 고쳐 쓴다.**
- 읽기: `LayeredGraph` 의 `step`·`elen`·`emask`·`scost` (`v3/features.py`, `v3/measure_controls.py`), `PIPE_SPECS` 상수.
- 쓰기: `v3/measure_negotiate.py` 가 `g.scost[...] += 가격` 으로 협상 가격을 더하고 비공개 `_item_cache` 를 손댄다.
- 소스 패치: `v3/astar_rg.py` 가 `astar_fast._search_generic` 의 선언 줄을 문자열로 찾아 바꾼다.
- 섹션 4) 측정도 같은 rg 코드를 쓴다.
- 섹션 3) (OPT) 은 지도 배열을 쓰지 않는다. 검증기·간섭 함수와 비공개 함수 3개 (`support_diag._support_of`, `verifier.session._reach`·`_segs`) 를 쓴다.

L3 의 자료형 변경·참조 공유·`_grow` 변경은 V3 를 **오류 없이 조용히** 깨뜨릴 수 있다 (특히 배열 참조 공유 + 제자리 쓰기 = 공유 캐시 오염 → 다음 배관 결과가 바뀜). 그래서 L3 와 API 규칙을 함께 정한다.

### 결정 (안)

1. **L3 (a)~(d) 를 결과 불변 가속으로 채택** (D53·D67 과 같은 종류).
   - (a) 밀집 서포트 표 제거 또는 유효 엣지만 희소 저장 (b) 노드 번호 int32, 장애물 마스크 uint16 (c) 배치층 표시가 엣지 목록 값을 복사하지 않고 참조 (d) A* 상태 배열 증가 = 2배 concatenate 대신 덩어리 목록 또는 1.25배, 인덱스 int32.
   - 비용·길이는 float64 유지. 자료형은 값 범위 안에서만.
2. **지도 조회 API 규칙** (`docs/verifier_api.md` 에 "지도 조회" 절 신설):
   - 공개 읽기 배열 목록·자료형·뜻을 적는다 (`step`·`elen`·`emask`·`scost`·`spack` 및 L3 후 이름). 목록에 없는 속성은 비공개 — 예고 없이 바뀔 수 있다.
   - 반환·노출 배열은 **읽기 전용** (`numpy writeable=False`). 제자리 쓰기는 즉시 오류가 난다 (조용한 오염 대신).
   - **공식 비용 덧셈 인자:** 라우터 호출에 엣지별 추가 비용 배열 (0 이상) 을 넘긴다 — 협상 가격용. 지도는 바꾸지 않는다.
   - **공식 휴리스틱 인자:** 상태 또는 노드별 하한 표를 넘긴다 (D125 rg 재구현의 `--heuristic` 과 같은 자리). 이것이 있으면 소스 패치가 필요 없다.
   - 두 인자를 쓰지 않으면 결과는 지금과 비트 동일.
3. **병합 순서:** API 규칙과 두 인자를 먼저 병합 → V3 에 통보, V3 가 새 API 로 옮긴 것을 확인 → L3 병합. V3 확인을 기다리는 동안 L3 는 브랜치에 둔다.

### 완료 기준 (보고 필수)

- 경로·J·확장 수·확장 순서 비트 동일, 결정성 (D72, 병렬 1 / 4), **E1 첫 해 41 바이트 동일.**
- **섹션 3) 이 쓰는 비공개 함수 3개 (`_support_of`·`_reach`·`_segs`) 의 영향 여부** — 시그니처·반환값·자료형이 바뀌는지, 바뀌면 무엇이 바뀌는지. 섹션 3) 고정 커밋 (`cd9c13e`, 이동 예정 `39dc146`) 과의 차이로 보고.
- V3 가 읽는 배열 (`step`·`elen`·`emask`·`scost`) 의 자료형·모양 변화 표.
- 메모리 재측정: (가) int_000 · (나) 밀집 50 · (다) 참조 품질선 proc_003 — 단계별 최대 RSS, D127 과 함께·따로.

## D127 진단 재라우팅 상한

### 배경

D74 진단 재라우팅 (라우팅 상한 × 4) 은 결과 (경로·J·성공·rip-up) 에 영향이 없는 보고용인데 최대 메모리를 정한다. 참조 품질선 (2²⁵) 의 진단은 2²⁷ 이라 약 28 GB 가 필요하고 (외삽), E1 참조 품질선 메모리 부족 4 시나리오 (D110 ③) 의 원인이다.

### 결정 (안)

**진단 상한 = min(4 × 라우팅 상한, max(라우팅 상한, 2²⁵))**

| 세트 | 라우팅 상한 | 지금 진단 | 새 진단 |
|---|---|---|---|
| 단일 블록 (E1 5 세트) | 2²² | 2²⁴ | 2²⁴ (같음) |
| 블록 쌍 | 2²³ | 2²⁵ | 2²⁵ (같음) |
| 참조 품질선 | 2²⁵ | 2²⁷ | **2²⁵** (= 라우팅 상한) |

- E1 6 세트 결과가 바뀌지 않는 식을 골랐다 (단순한 "2²⁴ 상한" 은 블록 쌍 진단을 2²⁵ → 2²⁴ 로 낮춰 E1 블록 쌍 라벨이 바뀔 수 있다).
- 참조 품질선은 진단이 라우팅과 같은 상한이라, 라우팅에서 상한을 소진한 배관의 진단은 대개 `diagnosis_inconclusive` 가 된다. 참조 품질선 결과표에 "진단 = 라우팅 상한" 을 적는다.
- 완료 기준: E1 첫 해 41 바이트 동일, 참조 품질선 4 시나리오 (proc_003·008·011·019) 재측정 — 끝나는지와 최대 RSS.

## D128 서포트 막힘 조회 `support_blockers`

### 배경

섹션 3) 이 서포트 충돌의 책임 배관을 찾느라 skeleton 비공개 함수 3개를 쓴다 (OPT PR #3 `opt/conflicts.py`). D120 요구사항 9 (책임 배관 쌍) 는 금지·선호 규칙용이라 서포트 막힘 (R7) 을 덮지 않는다. 비공개 함수를 그대로 공개하면 D126 같은 내부 변경 때마다 선수가 깨진다.

### 결정 (안)

- 힌트 (D100 `SupportHint`) 에 조회 함수를 더한다: **`support_blockers(pipe_id)` → [(막는 배관, 서포트 위치, 막힌 부재·형식, 막힘 종류)]**. 막는 배관이 없으면 빈 목록.
  - 뜻: 그 배관의 서포트 배치에서, 다른 놓인 배관이 없었다면 쓸 수 있었던 (면, 형식) 이 그 배관 때문에 불가가 된 경우 (부재 간섭, D80 ⑧) — R7 진단 (`docs/reports/s1_6.md` §10) 과 같은 정의.
- 조회 전용, 검증기 채점과 같은 함수 (`support_std.evaluate`), 결과 불변 시험 (힌트 호출 전후 채점 출력 비트 동일), R7 사례 목록 (`docs/reports/r7_cases.md`) 과 대조 시험.
- 호출 비용을 `docs/verifier_api.md` §4 에 적는다.
- 나올 때까지 섹션 3) 은 지금 함수를 써도 된다. 나오면 옮긴다. 옮긴 뒤 세 비공개 함수는 공개 약속 대상이 아니다.

## D129 판정 머신 — 같은 컨테이너 기준선 (Skeleton.Dec후보5, 섹션 3) 제기)

### 배경

- E1 동결 = Xeon 2.80 GHz · Python 3.13.16. OPT.Stage1 측정 = Xeon 2.70 GHz · Python 3.13.18. 클라우드 컨테이너라 세션마다 바뀐다 (E1 측정 때도 2.10 GHz 컨테이너로 시작해 버리고 다시 쟀다, D110).
- D68 (같은 머신 조건에서만 곡선 비교) 과 D122 (E1 동결 기준선 곡선은 다시 재지 않음) 가 부딪힌다. 판정이 벽시계 곡선 (D98) 이라 CPU 차이가 곡선을 옆으로 민다.
- 기준선은 결정적이다 (D72) — 다시 돌려도 경로·J·통과는 같고, **벽시계 축만** 바뀐다.

### 선택지

- **(가) 같은 컨테이너 짝 실행.** 선수가 E1 을 제출할 때 같은 컨테이너에서 기준선 anytime 을 다시 돌려 그 곡선과 비교한다. 동결 곡선은 참고로 남긴다.
  - 덤: 다시 돈 기준선 출력 (벽시계·메모리 제외) 이 동결 결과와 바이트 동일한지 확인한다 — 컨테이너·라이브러리 차이의 검사.
  - 비용: E1 기준선 측정은 동시 2 로 약 2.5 일 걸렸다. 선수 몫까지 같은 조건이면 제출당 약 5 일.
- **(나) 보정 계수.** 고정 보정 묶음 (세트마다 1 시나리오, 기준선 첫 해, 동시 2) 을 동결 머신과 제출 컨테이너에서 각각 재서 탐색 벽시계 비를 구하고, 동결 곡선의 시간 축을 그 비로 늘인다.
  - 보정 묶음은 두 번 재서 비가 ±3 % 안에서 같아야 쓴다. 비가 0.8~1.25 밖이면 (가) 로 간다.
  - 비용: 약 몇 시간. 한계: 메모리 대역·캐시 차이로 시나리오별 비가 다를 수 있다 (근사).
