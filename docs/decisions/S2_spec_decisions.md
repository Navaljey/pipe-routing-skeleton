## 공통 원칙

- 세 항목은 하나의 **배관 사양 체계**로 묶는다:

  ```
  유체 서비스 (service)  →  기본 pipe class  →  구경별 OD · kg/m · 관이음 무게
                         →  기본 보온 두께   →  유효 반경 r (D17)
                         →  압력/중력 구분
                         →  배관 이름 (line_no) · 3D 색
  ```

- 입력에 `service` 만 적어도 나머지는 표에서 따라온다. 배관별로 `pipe_class`·`insulation_thickness` 를 직접 적으면 그 값이 우선한다.
- **E1 불변:** 새 필드가 없는 배관은 지금과 같다 (class = DEFAULT = 현재 §3.1·§3.2 표, 보온 50 mm, 리듀서 없음, 접근 구역 없음, 출력에 새 필드 없음). E1 첫 해 41 시나리오 바이트 동일 시험을 건다 (S2 규칙 그대로).
- **생성기:** 새 기능은 모두 옵션으로만 켠다. 기본 경로는 같은 시드에서 비트 동일 (D115 보완 — V3 학습 시드 보호).
- **라우터–검증기 정합:** 배관 사양 값(OD·r·kg/m·관이음 무게)은 라우터·검증기·서포트·예약이 같은 함수(배관별 사양 조회)로 읽는다. 상수 표를 직접 읽는 곳을 남기지 않는다.

## D116 유체 서비스와 배관 이름

- **입력:** 배관 선택 필드 `service` (서비스 코드). 선택 필드 `line_no` 를 직접 적으면 그 이름을 쓴다.
- **서비스 표** (공개 레포 데이터 파일, `추정:` — 소유자가 사내 목록으로 교체 가능):

  | 코드 | 이름 | 압력/중력 | 기본 class | 기본 보온 (mm) |
  |---|---|---|---|---|
  | FO | 연료유 | 압력 | CS40 | 50 |
  | DO | 디젤유 | 압력 | CS40 | 0 |
  | LO | 윤활유 | 압력 | CS40 | 0 |
  | SW | 해수 | 압력 | CS40 | 0 |
  | FW | 청수 | 압력 | CS40 | 25 |
  | BG | 빌지 | 압력 | CS40 | 0 |
  | ST | 증기 | 압력 | CS80 | 75 |
  | CN | 응축수 | 압력 | CS40 | 50 |
  | CA | 압축공기 | 압력 | CS40 | 0 |
  | FF | 소화수 | 압력 | CS40 | 0 |
  | SD | 오수 | 중력 | CS40 | 0 |
  | DD | 갑판 배수 | 중력 | CS40 | 0 |

  표 열: 코드 · 이름 · 압력/중력 · 기본 class · 기본 보온 · 3D 색.
- **로더 (D33 확장):** 모르는 서비스 코드 = 오류. 서비스의 압력/중력과 `gravity_pipe`·`type_id` 가 다르면 오류.
- **배관 이름 (출력 routes[].`line_no`):** `{서비스}-{호칭경}-{번호 3자리}-{class}` (예: `FO-100A-001-CS40`, `추정:` 형식). 번호 = 시나리오 안에서 서비스별로 배관 순서대로 001 부터 (결정적). 리듀서 배관의 호칭경은 start 쪽.
- 서비스가 없는 배관은 `line_no` 를 출력하지 않는다 (E1 출력 바이트 동일).
- **리포트·3D:** 배관 이름 표시, 서비스별 색, hover 에 서비스·class·보온.
- 이름 자체는 경로에 영향이 없다. 서비스가 class·보온을 정하므로 그쪽을 통해서만 영향이 간다.

## D117 pipe class 와 배관별 보온

- **입력:** 배관 선택 필드 `pipe_class` (없으면 서비스 기본 class, 서비스도 없으면 `DEFAULT`).
- **class 표:** class 마다 재질 · 스케줄 · 구경별 {OD, kg/m} · 관이음 무게 {90° 엘보, 45° 엘보, 게이트밸브, 리듀서 (D118)}.
  - `DEFAULT` = 현재 §3.1·§3.2 (JIS G3454 Sch40 + JIS B2312 LR, D26 보간 포함) — 값과 계산 순서까지 그대로.
  - 공개 임시 표 (`추정:`, JIS 공칭값 기반 근사): `CS40` (= DEFAULT 와 같은 값), `CS80` (탄소강 Sch80), `SUS10S` (스테인리스 Sch10S).
  - 사내 class 표가 비공개이면 서포트 표 (D78) 와 같이 처리한다: 원본은 비공개 레포, 경로 = 환경 변수 `PIPE_CLASS_STANDARD`, 없으면 공개 임시 표. 출력 global `pipe_class_standard` {source, sha256}. 공개 문서에는 "사내 표준 기반(비공개)" 으로만 쓴다.
- **로더:** 모르는 class = 오류. class 표에 없는 구경 = 오류.
- **보온 (D17 수정):** 유효 반경 r = OD/2 + `insulation_thickness` + 10 mm. 보온 두께는 배관 입력값 → 없으면 서비스 기본값 → 없으면 50 mm. 0 허용 (보온 없는 배관, r = OD/2 + 10). D33 경고 "보온재 ≠ 50 mm" 는 삭제한다. 보온재 무게는 J 에 넣지 않는다 (지금과 같음).
- **서포트:** 선정표 조회는 지금처럼 호칭경 기준. 부재 치수의 OD 는 그 배관 class 의 OD.
- **고정층 캐시 키:** 구경 대신 (구경, r, 중력관 층 여부, 격자 변형). 보온이 다르면 r 이 달라 지도가 다르다.
- 최소 직진 (§3.3)·엘보 반경 R = 1.5D·L_max (D62)·서포트 간격 (§3.6) 은 호칭경 기준 그대로.

## D118 리듀서

- **입력:** 배관 선택 필드 `end_nominal_size`. `nominal_size` (start 쪽) 와 다르면 리듀서 **정확히 1개** 가 필요하다.
- **위치는 라우터가 고른다** (D111 밸브·D112 티와 같은 원칙).
- **규칙** (`추정:` 전부):
  - 동심형(concentric)만. 편심형은 이후 (M31).
  - 축 정렬 직관 위 (엘보 위·45° 구간 불가). 리듀서 중심에서 앞뒤 다음 관이음(엘보 접점·밸브·티·단자 면)까지 각 쪽 구경의 3D 이상.
  - 중력관: 하류(end) 쪽 구경 ≥ 상류(start) 쪽 구경. 압력관: 방향 제한 없음.
  - 구경은 D18 10종 안에서.
  - 리듀서 앞 구간은 start 구경, 뒤 구간은 end 구경으로 모든 규칙(r·kg/m·엘보·최소 직진·서포트 간격·L_max)을 적용한다.
- **비용:** 리듀서 무게 = class 표 값. 공개 임시 표가 없는 동안은 **큰 쪽 구경 45° 엘보 무게** (`추정:`, 정식 표가 오면 계수만 교체). 직관은 리듀서 중심까지 앞 구경, 그 뒤 뒤 구경으로 청구 (티와 같이 몸체 길이 별도 청구 없음).
- **기준선 라우터:** 상태에 "리듀서 놓음" 비트. 지도 = 두 구경 고정층 격자선의 합 (블록 쌍 관통 합성 층과 같은 방식), 노드·엣지 유효성과 마스크는 구경별로 두고 상태의 구경으로 고른다. 목표 = 도착 ∧ 리듀서 놓음. 리듀서는 서포트 고정점이 아니다. 최적성 보존 (가지치기 없는 Dijkstra 대조).
- **단자 예약 (D59):** 각 단자 구경 기준.
- **검증기:** 구간별 구경으로 collision·boundary·bend·gravity_slope·support 판정, 새 모듈 `reducer` (개수·직관 위·직관 길이·중력관 방향).
- **출력:** fittings `{"type": "reducer", "pos", "from_size", "to_size"}`, 구간별 구경, J 분해에 `reducer` 항목.
- 분기 다리의 리듀서, 배관당 2개 이상은 이후 (M31).

## D119 정비 공간 — 접근 구역

- **장애물 속성 추가 (D93 확장):** `access: true` = 접근 구역 (통로·사다리·해치 앞·장비 정비 공간).
  - 배관 진입 금지 (이격 r, 장애물과 같음). 서포트 부재 진입 금지 (부재 반폭). 지지면 아님 (supportable false), 관통 불가 (penetrable false) — 함께 적으면 로더 오류.
  - 높이가 제한된 박스이므로 통로 위 (박스 위) 공간은 배관이 지나갈 수 있다.
- **기본 치수** (`추정:`): 주 통로 폭 800 mm · 높이 2,000 mm (데크 상면에서). 장비 정비 공간 = 장비 한 수평 면 앞 깊이 800 mm × 장비 높이.
- **밸브 접근성 (D43 확장):** 시나리오에 접근 구역이 있으면, 밸브 전면 여유 공간 (D43 1 m³, 가능한 방향) 중 **하나 이상이 어떤 접근 구역과 500 mm 이내** (상자 간 거리, `추정:`) 여야 한다. 접근 구역이 없는 시나리오에는 적용하지 않는다 (E1·기존 시험 경로 불변).
  - 라우터: 밸브를 놓을 수 있는 위치를 엣지별로 미리 계산하고 (서포트 가능 구간과 같은 방식), 그 위치에서만 밸브 전이를 허용한다.
  - 검증기: `valve` 모듈에 접근성 판정 추가. 새 모듈 `access` = 배관 중심선(엘보 호 포함)·서포트 부재의 접근 구역 침범.
- **생성기 (`--access` 옵션):** 블록마다 주 통로 1개 (데크 상면, x 또는 y 방향 블록 관통, 폭 800 · 높이 2,000) 를 먼저 놓고 장비가 통로와 겹치지 않게 배치. 장비마다 노즐이 없는 수평 면 하나에 정비 공간. 단자 직진 구간 (D31) 이 접근 구역과 겹치지 않게 보장.
- 정비 공간과 다른 밸브 종류 (M30) 의 접근 규칙은 같은 함수로 확장한다.

- **일정 추정:** +6~9 작업일 (리듀서 3~4 · 접근 2~3 · 서비스·class 1~2, `추정:`).
