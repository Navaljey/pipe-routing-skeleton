## D134 (분기 계통 우선 도입 — D115 수정, 순서·단위 명시)

① **평가판 재배치:** E2 = E1 + 내부 구조재 세트 + 분기·헤더 세트 (+ 큰 맵 세트), E3 = E2 + 밸브 세트 + 선호 규칙 세트 (D120). 실제 규모 세트(D123)는 템플릿 v2부터 분기 계통을 포함한다.

② **skeleton 순서:** S2-3 (분기 1개 정확 풀이) → S2-4 (헤더 순차 근사 + 다중 배관) → S2-2 (밸브). S2-T·S2-M은 그대로.

③ **다중 배관 단위 = 계통:** 순서 = 주관 구경 내림차순, 같으면 주관 맨해튼 거리. rip-up은 계통 전체를 들어내고 다시 깐다. 단자 예약(D59)은 놓이지 않은 계통의 모든 단자(주관·다리)에 둔다. 실패 분류(D51·D74)와 Σ 단독 J(D101)는 계통 단위로 계산한다.

④ **검증기 명시 항목:** 나무 연결성 — 다리마다 시작점이 자기 주관 직관 위 1 mm 안, 끝점이 자기 단자, 다리끼리 연결 없음(사이클 불가).

⑤ **D112 세부는 그대로:** 티 무게 0 (M15와 함께 재검토), 티는 주관 위에만 (하위 분기 → M37), 다리 순서 = 큰 구경 → 먼 것, 분기 뒤 주관 축소는 M31.

⑥ **E1 불변:** 분기 없는 배관은 결과 비트 동일 (S2-0 시험 유지).

### 옮겨 적을 때 함께 고칠 곳 (의미 변경 없음)

- CLAUDE.md §1.15 D115 행 끝에 "→ **D134 로 수정**: E2 = E1 + 내부 구조재 + 분기·헤더 (+ 큰 맵), E3 = E2 + 밸브 + 선호 규칙" 을 붙인다. D70 의 E2·E3 문구에도 같은 화살표.
- §8 단계표: S2-3 · S2-3b · S2-4 를 S2-2 앞으로. S2-6 동결 행의 세트 구성도 D134 ① 로.
- §11 R6: "skeleton 준비물 = 평가셋 E3" → "분기·헤더 = E2, 밸브 = E3 (D134)".
- `docs/v3_contract.md` 단계별 평가판 표: 3단계 (다중 배관) = E2 (분기·헤더 포함, 단위 = 계통), 4단계 = E3 (밸브·선호).
- 검증기 branch 모듈 설명 (§6.1) 에 연결성 한 줄.

### 정의 보충 (D134 ③ 의 계산 방식 — 구현 기본값 `추정:`)

- 계통 = 입력 배관 하나 (주관 + `branches`). 분기 없는 배관 = 다리 0 인 계통 → 지금과 같다 (⑥).
- 계통 성공 = 주관과 모든 다리가 Layer 0 통과 (D112 "헤더 = 배관 단위 실패" 와 같음). D77 ② 통과 배관 수는 계통 수로 센다.
- 실패 분류: 계통 단독 재라우팅 (다른 계통·예약 없음, D74 진단 예산 = D112 계통 예산 × 4) 이 성공하면 간섭, 실패하면 개별 경로. 막는 상대도 계통 id 로 기록.
- Σ 단독 J (D101): 계통 단독 J (주관 + 다리 합).
- rip-up 대상 선정 (D50 ④): 실패 계통의 단독 나무와 충돌하는 기존 계통 전체.

## M37 하위 분기 (티를 다리 위에)

- 내용: 다리에서 다시 갈라지는 나무 (2단 이상). Takahashi–Matsuyama 류 Steiner 근사처럼 나무 전체에서 뻗는 기준선, 출력 `tree` 의 다단 표현, 검증기 연결성 일반화가 필요하다.
- 해제 조건: E2 동결 후, 실제 규모 템플릿의 헤더에서 필요성이 확인될 때.

## D134 보완 (2026-11-23 소유자 승인 — 섹션 3)·V3 질문 회신)

1. **명확화:** D134 ③ 은 **기준선** 다중 배관의 규칙이다. 선수는 슬롯 내부에서 무엇을 다시 깔지 자유 (다리 하나만 다시 깔기·티 이동 포함, v3_contract §c · D121) — 심판은 최종 나무만 채점한다.
2. **다리 좌표 순서:** 출력 `tree.legs[].waypoints` 는 기하 순서 (티 → 다리 단자, S2-0 스키마 그대로). 흐름 방향은 `flow`. 구배 (gravity_slope, D61) 는 **흐름 순서**로 판정 — 합류 (`in`) 다리는 뒤집어 단자 → 티로 본다. 분기각·서포트도 같은 규약.
3. **통과 다리 수 (보조 지표):** 출력 routes[] `legs_passed` / `legs_total`, global `legs_passed_total`. 판정 (D77) 에는 쓰지 않는다 — 계통 성공 = 주관·모든 다리 통과 그대로 (D112 Q10).
4. **공개 호출 (S2-4):** 나무 라우터 = 라우터 슬롯과 같은 형태 `router(scenario, pipe, time_limit, placed)` (placed = 놓인 계통 목록, 반환에 `tree`). 다리 하나 다시 까기 = `leg_router(scenario, pipe, main_waypoints, leg_id, placed, budget)` — 주관 고정, 주관 직관 위 목표 집합 탐색 (기준선 순차 근사가 쓰는 함수 그대로). `docs/slots.md`·`docs/verifier_api.md` 에 문서화.
5. **같은 계통 안 D 형식 공유 서포트 허용:** 주관 ↔ 자기 다리, 다리 ↔ 다리도 다른 배관처럼 D82 조건 (D89 포함) 을 적용한다. 몫 = D81 단위중량 비례.
6. **책임 조회 단위:** `support_blockers` (D128) 와 D120 요구사항 ⑨ 의 막는 쪽 = `(pipe_id, leg_id | "main")`. 분기 없는 배관은 `"main"` 만 — 기존 결과 불변.
7. **계통 안 미배치 단자 예약 (D59 확장):** 계통의 일부를 깔 때, 같은 계통에서 아직 놓이지 않은 다리의 단자 직진 구간도 예약한다 (주관을 깔 때 = 모든 다리 단자, 다리를 깔 때 = 남은 다리 단자). 길이·이격은 D59 그대로.
8. **같은 계통 안 간섭 규칙 (`추정:`):** 예외 = **티 몸체 구역**만 — 다리의 첫 직관 중 티 중심에서 3D_분기까지 ↔ 주관 직관 중 티 중심 ±3D_주관 구간, 이 두 조각 사이만 이격 판정에서 뺀다. 그 밖은 다른 배관과 같다 (다리 ↔ 자기 주관, 다리 ↔ 다리 모두 r₁ + r₂, 엘보 호 포함). 기준선 정확 풀이의 자기 간섭 판정 (§7 Q9) 도 이 규칙.
9. **진단 예산:** D127 식 그대로 — 라우팅 상한 2²² × (다리 + 1) 에 min(4 × 라우팅, max(라우팅, 2²⁵)). 다리 5 개 = 2²⁵ (약 3,355만). S2-4 측정에 다리 수별 진단 재라우팅 최대 RSS 를 따로 보고, 넘치면 "자원 초과" (D123 ③).
10. **티 직관 구간은 다른 계통에 예약하지 않는다:** 티는 주관이 놓일 때 정해지고 놓인 주관은 이미 장애물이다. 티 3D 직관 규칙은 같은 배관 위 관이음 사이 규칙이라 다른 계통 배관과 무관하다.
