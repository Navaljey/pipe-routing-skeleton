## 배경

소유자가 실제 기관실 2nd deck 모델 화면 (배관·트레이 없는 것 / 있는 것) 을 사양 세션에 보여 줬다. 사양 세션은 화면에서 **배치 규칙만** 읽어 가상 템플릿을 만들었다 (D124 ④ — 좌표·이름은 옮기지 않음, 화면은 레포에 두지 않음).

읽은 규칙: 데크·격벽으로 나뉜 방 (청정기실·공작실/창고) · 촘촘히 반복되는 구조 부재 (천장 종늑골·트랜스 웹·외판 쪽 수직 웹) · 가운데 기관 케이싱 (주기관 상부·배기 업테이크) · 케이싱 둘레 고리 통로와 계단으로 가는 통로 · 바닥 개구부와 난간 · 탱크·청정기·펌프·공기탱크 묶음 · 배관과 케이블 트레이가 통로 위를 따라 같은 높이로 모여 지나감 (숙련공 배치 — R7·D120 의 목표 장면).

템플릿 수치 (2026-11-22 소유자 승인 — 경험값, 특정 선박 값 아님): 데크 간 높이 5,200 · 천장 종늑골 간격 800 / 단면 250 × 90 · 트랜스 웹 간격 3,200 / 깊이 800 · 구역 36 × 30 m · 고리 통로 폭 1,000 · 케이싱에서 1,200 · 배관 33 줄 (FO·LO·SW·FW·CA·ST·CN·FF·BG·SD·DD) 에서 생성기가 30~50 개로 늘림.

## M36 — 첫 템플릿 등록

- `templates/er_2nd_generic_a.yaml` v1 을 첫 템플릿으로 등록한다 (D124 ⑤). **M36 은 열어 둔다** — 템플릿 종류 추가 (목표 4~5 종) 가 남아 있다.
- 템플릿 형식 (키 이름·펼치는 규칙) 은 S2-T 에서 Code 가 로더를 만들며 확정하고, 바꾼 것은 이 파일에 이어 적는다. 의미는 바꾸지 않는다.
- 평가용·학습용 구분 (D123 ⑤): 이 템플릿은 **첫 측정용 (노드 수·메모리·시간)** 이다. 평가용으로 쓸지는 템플릿이 2종 이상 생긴 뒤 정한다.

## D130 바닥 개구부

- 구역 바닥의 사각 영역을 **바닥 개구부** 로 지정할 수 있다 (템플릿 `floor_opening: true`, 시나리오 입력 최상위 선택 필드 `floor_openings: [{id, min:[x,y], max:[x,y]}]`).
- 개구부 위에서는 **바닥 지지면을 쓸 수 없다** — 바닥 쪽 C·D 형식 부재 (다리) 가 개구부에 닿으면 그 조합 불가 (D80 ③ 같은 선택 함수 안에서). 천장 지지는 그대로.
- 개구부를 지나 아래 데크로 가는 배관 = 개구부 안에 놓인 하부 경계 단자 (D35·D96 규칙 그대로). 개구부 자체는 배관 장애물이 아니다.
- 난간 (`handrail`) 은 높이만큼의 접근 구역 띠 (D119) 로 펼친다 — 배관은 난간 위를 지나갈 수 있다.
- 라우터–검증기 정합: 서포트 선택 함수 (`support_std.evaluate`)·라우터 u·서포트 보조 격자선 (D87 ①) 이 같은 판정을 쓴다. 개구부가 없는 시나리오는 결과 불변 (E1 첫 해 41 바이트 동일).

## D131 케이블 트레이

- 케이블 트레이 = **먼저 깔린 고정 장애물** (장애물 종류 `tray`, supportable false · penetrable false). 배관은 트레이와 유효 반경 r 이상 떨어져야 하고, 서포트 부재도 트레이를 피한다 (부재 반폭).
- 근거: 실제 설계에서 트레이와 배관은 같은 공간을 다투며, 트레이를 빼면 통로 위 공간이 실제보다 넓어 보인다.
- 트레이 경로는 템플릿이 정한다 (통로를 따라가는 규칙). 트레이 배치 최적화는 범위 밖.
- 트레이 자체의 서포트·무게는 모델에 넣지 않는다 (J 에 없음).

## D132 깊은 웹 (트랜스 웹 프레임)

- 천장 아래 트랜스 웹 = D113 스티프너 계열 (supportable true · penetrable false). **배관은 웹 사이로 다니거나 웹 아래로 지난다.**
- 웹의 정해진 구멍으로 관통하는 것은 M27 (거더·웹) 범위로 남긴다 — 지금은 불가.

## D133 구역 높이 범위

- 설계 구역의 z 범위 = **이 데크 윗면 (z = 0) → 윗데크 판 아랫면 (z = H)**. 윗데크 아래에 매달린 구조 (종늑골·웹) 는 구역 안의 장애물로 펼친다.
- 바닥 지지면 = 데크 윗면, 천장 지지면 = 윗데크 판 아랫면 (D22 그대로). 천장 구조 부재의 아랫면도 supportable 이므로 서포트 선택 함수가 가장 가벼운 쪽을 고른다 (D80 ③).
- 사진의 "바닥에서 2,000 mm 뷰" 는 보기용 단면일 뿐 구역 범위와 무관하다.

## S2-T 범위 (이 결정 반영)

1. 템플릿 로더·펼치기: 구조 규칙 → 장애물 (같은 좌표 공유, D124 ③) · 통로·계단·정비 공간 → 접근 구역 · 개구부 (D130) · 트레이 (D131) · 장비·단자 · 배관 목록 → 시나리오 JSON. 같은 템플릿·같은 시드 → 비트 동일, 템플릿·시나리오 sha256 기록.
2. 변형 생성 (`variation`): 학습·검증 시드 범위에서 생성 가능 (D115).
3. 첫 기준선 측정: 배관 30 → 50, 노드 수·격자 좌표 수 (축별)·메모리·시간·통과·실패 분류. 메모리 넘치면 "기준선 미도달 — 자원 초과" (D123 ③). 이 결과로 M35 (큰 머신)·L1 (지연 평가) 착수 여부를 판단한다 (D126 보고서 §8 ③).
4. 시험: 펼치기 결정성 · 개구부 위 바닥 지지 불가 (라우터·검증기 일치) · 트레이 회피 · 개구부·트레이 없는 시나리오 E1 첫 해 41 바이트 동일.
