## 원인 (사양 세션 진단, 2026-11-23)

- `scenario.terminal_straight_length` 는 강제 직관을 **단자 → 꺾임점** 길이로 잡는다 — 경계 = max(3D, r) **+ t₉₀**, 노즐 = max(§3.3, t₉₀). `terminal_straight_blocked` 는 이 구간 전체를 곧은 배관으로 보고 장애물 이격을 잰다.
- 실제 배관의 곧은 부분은 꺾임점에서 t 앞 (엘보 접점) 에서 끝나고, 그 뒤는 엘보 호다. 호는 라우터가 고른 꺾는 방향으로 휜다 — 장애물이 꺾는 반대쪽에만 있으면 막히지 않는다. 함수 설명의 "가장 짧은 허용 길이, 90° 꺾임 기준" 도 틀렸다 (45° 는 t 가 더 짧다).
- P009: start (25650, 0, 2880) → +y. 장애물 OBS_013 = y ≥ 1390 · z ≥ 3040. 판정 길이 1,350 끝 이격 164.9 < r. 기준선 경로는 y = 1,350 에서 −z 로 90° — 곧은 부분은 y = 900 까지, 실제 중심선 최소 이격 **332.4 mm** ≥ r.

## D135 (D106 (b) 정정 — 반드시 곧은 구간만 판정)

① "규칙상 불가능 — 단자 직관 막힘" 은 **꺾는 방향·각도와 무관하게 반드시 곧은 구간**만으로 판정한다 — 경계 단자 = max(3D, r) (D96 강제 직관), 노즐 = min_θ max(§3.3 − t_θ, 0) (θ ∈ {45, 90, 135}, 실질적으로 0 — 노즐 점의 이격은 D28 이 보장). 그 뒤의 엘보 호는 꺾는 방향을 라우터가 고르므로 증명에 쓰지 않는다. 판정 함수는 지금처럼 `terminal_stub` + `obstacle_clearance` (장애물과 r 미만이면 막힘).

② **E1 → E1.1 (분류 정정판)** — D71 의 "심판 변경은 판 올림" 에 따른다. 경로·J·곡선은 다시 돌리지 않고, E1 동결 첫 해·예산 끝 출력에서 분류 (분모 제외·`required_pipes`·`excluded_infeasible`·`full_success`·`fail_class`) 만 정정 기준으로 다시 계산한다. 분류 필드를 뺀 나머지 출력이 E1 과 바이트 동일해야 한다. `docs/eval_set_E1.md` 에 E1.1 절을 덧붙인다 (E1 원문은 지우지 않는다).

③ D33 로더 경고 (단자 최소 직진 구간 막힘) 는 경고이므로 지금 길이 그대로 둔다 — "꺾기 어려움" 의 신호로는 유용하다. 생성기의 단자 직진 보장 (D31·D107, `d94_stub_len` = +t₁₃₅) 은 더 넉넉한 보장이라 그대로 — 기존 생성기 출력 비트 동일 (D115 보완).

④ 선수 통보: V3·OPT 가 E1 분모 730 으로 계산한 보고는 745 로 바뀐다. 판정 순서 (D77) 와 ①·② 값은 같다.
