## D136 템플릿 형식 v2 (D124 ③ 구체화)

① **성격 블록.** `attribute_defaults: {그룹: {supportable, penetrable, penetration_axis, access}}` (그룹 = 템플릿의
구분 키 — ceiling_longitudinals · ceiling_web_frames · side_shell_frames · pillars · bulkheads · casing_wall ·
casing_contents · stairs · equipment · cable_trays · passages · maintenance · handrails),
`attribute_overrides: {장애물 id: {…}}`. 우선순위 = 개별 > 그룹 > D93 기본 (모두 false). `access: true` 와
`supportable`·`penetrable` true 를 함께 쓰면 로더 오류 (D119). 성격을 템플릿 본문 항목 안 (`attributes:`) 에 적는
v1 방식은 쓰지 않는다 — 한 곳에서만 읽는다. 펼친 시나리오의 장애물에는 최종 값을 적는다.

② **장비 노즐.** `equipment[].nozzles: {이름: {face, at, size}}` (케이싱 안 장비도 같다).
`face` ∈ east (+x) · west (−x) · north (+y) · south (−y) · top (+z) · bottom (−z) (로더 해석 T1 과 같음).
`at` = 옆면이면 [면 안 수평 거리 (그 면의 작은 좌표 쪽 모서리부터), 높이 (장비 바닥부터)], top·bottom 이면
[x 거리, y 거리] (장비 최소 모서리부터). 노즐 점이 면 밖이면 로더 오류. 단자 `pos` = 노즐 점에서 면 법선 바깥으로
유효 반경 r (10 mm 올림, D28), `dir` = 법선 바깥 (출발) / 안쪽 (도착) (D29), `host` = 장비 id.
변형 (`variation.equipment_pos·size`) 에서 노즐은 장비와 함께 움직인다 — `at` 은 장비 크기 비율이 아니라 mm 그대로,
장비가 줄어 노즐이 면 밖이 되면 그 변형을 다시 뽑는다.

③ **단자 표기.** `장비.노즐` · `DECK_DN(x, y)` · `DECK_UP(x, y)` (하부·상부 데크 관통 경계 단자, D35) ·
`BHD(격벽 id, u, z)` (u = 격벽 면 안 수평 좌표 — x 축 격벽은 y, y 축 격벽은 x). v1 의 `장비.면` (면 가운데) 과
`BHD(id)` (위치 없음) 는 쓰지 않는다. 노즐 구경 ≠ 배관 (또는 다리) 구경이면 로더 오류.

④ **배관 = 계통 (D134).** `pipes: [{svc, size, from, to, legs: [{size, to} | {size, from}]}]` — `legs` 0~5,
`to` = 갈래 (flow out), `from` = 합류 (flow in), 다리 구경 ≤ 주관 (D112). 중력 서비스 (D116) 의 다리는 `from` 만.
펼친 시나리오의 `branches[]` 로 옮긴다. 배관 이름 (`line_no`) 은 D116 규칙으로 로더가 붙인다.

⑤ **통로·문·트레이 규칙을 본문에.** 문 = `passages.doors: [{id, on: 격벽 id, at: [x, y]}]`, 곁가지 통로 = 목표 (계단·문)
중심에서 고리의 가까운 변까지 한 축 직선, 트레이 수직 내림 = `{drop_from, at: [x, y], to_z}`. 템플릿에 없는 규칙을
로더가 해석하지 않는다 — 없으면 로더 오류. 로더의 `INTERPRETATIONS` 는 형식으로 옮기고 남는 것만 둔다.

⑥ **판 번호.** 템플릿 최상위 `format: 2`. 로더는 형식 2 만 읽는다 (v1 파일은 v2 로 바꾼다 — 첫 측정은 아직 없음).
출력 `meta.template` 에 템플릿 sha256 (D124 ③) 과 `format`.

⑦ **펼치기 코드 하나.** 편집기 (`tools/template_editor/`) 는 S2-T 로더의 펼친 결과 (+ 로더가 내는 점검 결과) 를
그린다. 편집기 쪽 펼치기 (`expand.py`) 는 로더가 형식 2 를 읽게 되면 지운다. 점검 = 장애물 겹침 (의도된 것 제외 규칙도
로더에) · 단자 직진 구간 (노즐 = max(§3.3, t₉₀), 데크·격벽 관통 = max(3D, r) + t₉₀) 이 다른 장애물과 r 이상 ·
접근 구역 침범 없음 — 로더 경고 (D33 과 같은 층).

## D137 템플릿 평가용 · 학습용 구분 (D123 ⑤ 구체화)

① 템플릿마다 최상위 `use: eval | train` (`추정:` 기본 없음 — 적지 않으면 로더 오류).
② **eval 템플릿:** 소유자가 "실제 같은 배치" 로 확인한 것만. 평가판 (E2·E3) 에 넣을 때 시나리오 2~3 개 (D123 ⑤) 를
평가 시드 범위 (20260000~20269999) 로 펼쳐 동결한다. **학습·검증 시드 (3xxxxxxx · 4xxxxxxx) 로 펼치는 것을 금지**한다
— 로더가 eval 템플릿 + 학습·검증 시드 조합을 거부한다. 레포가 공개라 내용은 선수가 볼 수 있다 — 막는 것은 학습 재료
생성이다 (D71 계약으로 지킨다).
③ **train 템플릿:** 학습·검증 시드로 자유롭게 펼친다. 평가판에는 넣지 않는다.
④ **일반화 지표 (leave-one-template-out):** eval 템플릿과 같은 "종류" (E/R 데크·펌프룸 등) 의 train 템플릿이 있어도
된다 — 같은 파일·같은 배치는 안 된다. 템플릿 세션이 템플릿마다 종류를 적는다 (`kind:`).
⑤ 첫 템플릿 `er_2nd_generic_a` 는 `use: train` 으로 둔다 (첫 측정·편집기용, 레포·대화에 노출이 많았다).
eval 템플릿은 새로 만든다 — 템플릿 세션 몫.

## D138 단계 판정 재현 (V3·OPT 공통, D121 선수 계약)

① **대상 = 판정값을 만드는 측정만:** 단계 통과·종료 판정, 기준선 대비 우위를 주장하는 방법 채택, E판 제출 (D129).
일상 실험 측정은 대상이 아니다.
② **재현 = 그 코드를 작성하지 않은 세션** (사양 세션이 지정 — skeleton Code 또는 새 재현 세션) 이 보고서의 명령·
시드·커밋 (선수 레포 + skeleton) ·환경으로 다시 돌린다. 판정 지표 (D77 ①②③ · 통과 집합) 는 결정적이므로 (D72)
**바이트 동일**해야 한다. 벽시계는 같은 컨테이너 짝 실행 (D129 (가)) 으로만 비교하고 재현 조건에 넣지 않는다.
③ 보고서 필수: 재현 명령 · 선수 커밋 · skeleton 커밋 · 비공개 표 source·sha256 (D78·D117) · 머신 사양 · 시드 목록.
④ 재현 결과가 다르면 판정을 보류하고 원인 (선수 코드 · 환경 · 심판) 을 먼저 찾는다.
⑤ 첫 적용 = V3 §40 (변형 T, E1.1 41 시나리오).
